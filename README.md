# data-governance

## 创建项目
记得在.gitignore同级目录建一个.env文件，然后写入  
API_KEY=xxxxxx
MILVUS_URI=xxxxxx  
MILVUS_TOKEN=xxxxxx  
（这里API_KEY默认来源于火山引擎，模型默认使用deepseek-v4-flash；若使用其他平台的API_KEY，则需要添加URL和模型声明，例如：
BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-pro）

## 思路同步
1. 不考虑到数据示例包含说明性文字的情况，默认为真实数据。
2. 落标处理中，非代码枚举类的流程不考虑换域，主要原因是换域的情况太少了：只有当某个标准名称含义都特别合适，只有域类型不正确，且没有其他合适的标准时，才考虑换域。如果需要的话，把这个逻辑放在标准维护模块中，即发现拟新增的标准和某个已有标准特别相似，只有域类型不同，那就给已有标准换域。并且，换域过程不需要考虑权威系统相关逻辑，因为无论如何都要治理人员和权威系统沟通后才有结果，因此智能体统一按非权威系统来处理。
3. quality_check不对代码枚举类的域类型和数据示例，域类型和字段所属类型联动检查。因为很多代码枚举类提上来是没有代码的，它数据示例那一栏填的是码值。并且去掉也没影响。
4. quality_check不对业务定义和字段所属类型，字段所属类型和数据示例，字段名和数据示例联动检查。比如字段”父资产类型“，定义里明说了包含股票、基金、债券，但申请单上写成了文本类。因为有特例存在，比如他就是想建一个文本类，只能留给治理人员判断。但似乎可以给治理人员一个提示？
