## 思路同步
1. 整体思路：智能体没办法在落标处理前，预判到申请单信息需要细化到什么粒度，因此申请单信息尽可能充足，智能体根据提供的信息尽可能落标。少量模糊地带（如字典“资质审核结果代码”和“特惠结果审核代码”，枚举值一样，前者是对进行商户资质审核，后者对商户进行特惠审核），本质上是要求提单子的人结合已有标准，进一步补充信息，来帮助治理人员判断使用哪一个已有标准。这一块儿需要交给治理人员来做。
2. 不考虑到数据示例包含说明性文字的情况，默认为真实数据。
3. 落标处理中，非代码枚举类的流程不考虑换域，主要原因是换域的情况太少了：只有当某个标准名称含义都特别合适，只有域类型不正确，且没有其他合适的标准时，才考虑换域。如果需要的话，把这个逻辑放在标准维护模块中，即发现拟新增的标准和某个已有标准特别相似，只有域类型不同，那就给已有标准换域。并且，换域过程不需要考虑权威系统相关逻辑，因为无论如何都要治理人员和权威系统沟通后才有结果，因此智能体统一按非权威系统来处理。
4. quality_check中，不对标志类/代码枚举类的域类型和数据示例，域类型和字段所属类型联动检查。很多时候数据示例那一栏填的是码值，要求开发填成代码就太严苛了，不检查也不影响后续处理步骤。
5. enum_standard_mapping中，标准的体系是 字典-枚举代码-枚举值，去掉了域
6. enum_standard_mapping中，默认国标也有枚举值。不允许编码规则形如“遵循《GB/T 12406-2008 表示货币和资金的代码》”的枚举代码出现在标准库中，这是无效信息。
7. enum_standard_mapping中，枚举代码到底是修改还是新增的判断，应该和复用字典、新增字典但复用枚举代码完全分开。从这个筛选逻辑出来的枚举代码，无论它对应的操作是复用枚举代码，还是修改枚举代码，都不应该影响后面的决策。换句话说，不应该存在下面这种情况：相比于标准A，标准B的枚举值和待落标字段更匹配，但A本身的业务含义和待落标字段更匹配，最后经过综合，选了标准B。
8. pd.read_excel直接读取，单元格格式判断的逻辑应该治理平台实现，我们统一当成文本。
